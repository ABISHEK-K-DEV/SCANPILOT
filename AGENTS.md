# ScanPilot — notes for coding agents

Offline-first document scanner & PDF editor. Expo SDK 58, React Native 0.88 (New Architecture), React 19.3, strict TypeScript. Read `README.md`, `IMPLEMENTATION_PLAN.md`, `docs/ARCHITECTURE.md` first.

## Rules

- Work milestone by milestone; update `IMPLEMENTATION_PLAN.md` and `README.md` with every feature.
- Routes only in `src/app/`. Business logic in `src/services/` (no React). Native SDKs only behind adapters in `src/native/`.
- PDF operations go in `src/services/pdf/pdfService.ts` as pure `Uint8Array` functions **with Jest tests**.
- Never upload or transmit document contents. No analytics SDKs. No paid/trial SDKs. No AGPL/GPL dependencies (`npm run licenses:check`).
- Never overwrite an original document in place — write a new file atomically (`writeBytesAtomically`).
- Every button must work; unavailable features are shown disabled with a "Soon" badge (`src/features/tools.ts`).
- Always include loading, empty and error states. Icon-only controls need `accessibilityLabel`.
- `expo-file-system` `File.write/move/copy` return promises — always await (lint enforces this).
- Expo APIs change every SDK: check the installed package's `.d.ts` files rather than memory.

## Commands

```bash
npm install                 # (npx expo install <pkg> resolves SDK-compatible versions when online)
npx expo run:android        # build + run the development build (Expo Go is NOT supported)
npm start                   # Metro for an installed dev build
npm run verify              # typecheck + lint + tests + licence audit
npm run test:pdf-readers    # validate generated PDFs with pdfinfo + pypdf
```

`android/` and `ios/` are generated by `expo prebuild` and git-ignored — configure native behaviour in `app.json` / config plugins.
